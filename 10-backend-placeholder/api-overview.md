# API Overview

## Architecture

```
┌─────────────────────────────────────────────────────────────────┐
│  Frontend (React + Vite, port 5173)                              │
│  Axios · CSRF interceptor · session cookie                       │
└──────────────────────┬──────────────────────────────────────────┘
                       │  /api/*  /media/*   (Vite dev proxy)
                       ▼
┌─────────────────────────────────────────────────────────────────┐
│  Django 5.1 + DRF (port 8000)                                   │
│  ┌─────────────┐ ┌────────────┐ ┌───────────┐ ┌──────────────┐  │
│  │  accounts   │ │  hazards   │ │moderation │ │    common    │  │
│  │ auth · admin│ │ reports    │ │ actions   │ │ email helper │  │
│  └─────────────┘ └────────────┘ └───────────┘ └──────────────┘  │
│  ─────────────────────────────────────────────────────────────  │
│  Permissions: IsCitizen · IsModeratorUser · IsPlatformAdmin      │
│  Throttling:  login 10/min · register 5/hr · reset 10/min        │
│  Documentation: drf-spectacular → OpenAPI 3.0                    │
└──────────────┬──────────────────────────────┬───────────────────┘
               │                              │
               ▼                              ▼
     ┌───────────────┐              ┌──────────────────┐
     │ SQLite/Postgres│              │  media/hazards/  │
     │                │              │  YYYY/MM/*.webp  │
     └───────────────┘              └──────────────────┘
```

In development the Vite dev server proxies `/api` and `/media` to `127.0.0.1:8000`, so the
frontend uses same-origin relative paths and CORS/CSRF never actually cross origins.

## Response conventions

### Renderers and parsers

| Concern | Configuration |
|---|---|
| Renderers | `JSONRenderer`, `BrowsableAPIRenderer` |
| Parsers | `JSONParser`, `FormParser`, `MultiPartParser` |
| Pagination | `PageNumberPagination`, `PAGE_SIZE: 20` |
| Primary keys | `BigAutoField` |

`MultiPartParser` is what allows photo uploads through the same endpoint as JSON.

### Paginated envelope

```json
{
  "count": 42,
  "next":  "http://127.0.0.1:8000/api/v1/hazards/?page=2",
  "previous": null,
  "results": [ { "id": 1, "...": "..." } ]
}
```

The frontend defensively handles both `{results: [...]}` and a bare array. **Only the
hazards endpoint paginates** — every other endpoint returns a bare array. This asymmetry
is why the frontend has the defensive check; see
[`known-inconsistencies`](#known-inconsistencies).

## CORS and CSRF

### Development mode relaxation

```python
if DEBUG:
    CORS_ALLOW_ALL_ORIGINS = True
    # Auto-trust LAN subnets for phone/tablet testing
```

This exists so a developer can open the app on a phone on the same Wi-Fi and have it
work. It is **insecure by design and must not ship** — `DEBUG=False` restores the
explicit allowlists.

With `DEBUG=True`, CSRF trusted origins are expanded with wildcard patterns for common
private subnets (`192.168.*`, `10.*`, `172.16–31.*`) across `http`/`https` on ports
5173, 8000, 3000, and the default port, plus `*.local` and any explicit `LAN_IP`.

### Production posture

| Concern | Requirement |
|---|---|
| `DJANGO_DEBUG` | Must be `False` |
| `DJANGO_SECRET_KEY` | Must be set to a real secret |
| `ALLOWED_HOSTS` | Must list real hostnames |
| `CORS_ALLOWED_ORIGINS` | Must list the deployed frontend origin |
| `CSRF_TRUSTED_ORIGINS` | Must list the deployed frontend origin |
| Cookies | `Secure` and `SameSite` flags for HTTPS |
| Media | Local filesystem is unsuitable for multi-instance deploys — use object storage |

## Static and media

| Setting | Value |
|---|---|
| `STATIC_URL` | `static/` |
| `STATIC_ROOT` | `<backend>/staticfiles` |
| `MEDIA_URL` | `/media/` (overridable) |
| `MEDIA_ROOT` | `<backend>/media` |
| Upload path | `hazards/%Y/%m/` — year/month sharded |

Media is served by Django **only when `DEBUG=True`**:

```python
if settings.DEBUG:
    urlpatterns += static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
```

In production, media must be served by a reverse proxy or CDN.

## Known inconsistencies

| Issue | Impact | Recommendation |
|---|---|---|
| **Only `/hazards/` paginates** | Other endpoints return bare arrays, so the frontend must handle both shapes | Either paginate everything or return bare arrays everywhere; the frontend's `response.results ? response.results : response` check should be able to be deleted |
| **`freshness` vs `freshness_info`** | The serializer exposes `freshness`; the landing page reads `freshness_info`. `LandingPage` passes `freshness_info` to a component expecting `freshness`, so live-pulse cards fall back to default copy | Remove `freshness_info` from the frontend, or rename the model property to match the serializer |
| **Confirmation threshold is hardcoded to 3** | `confirm()` uses `CONFIRMATION_THRESHOLD = 3` rather than reading `PlatformSettings.confirmation_threshold`, so the admin setting has **no effect** on auto-confirmation | Read the value from `PlatformSettings.get_settings()` |
| **`freshness_hours` setting is unused** | `HazardReport.freshness_info` hardcodes 1 day / 2 days, so the admin setting has **no effect** | Use `settings.freshness_hours` as the stale boundary |
| **`allow_anonymous_map_view` is not enforced** | The setting exists and is admin-editable, but no view checks it | Gate `HazardReportViewSet` list/retrieve on it, or remove the setting |
| **`emergency_notice_enabled` is not enforced** | Exposed in the API response but the advisories are frontend-only | Either check it in the report flow or remove it |
| **Duplicate moderator permission class** | `IsModeratorOrAdmin` in `moderation/views.py` and `IsModeratorUser` in `accounts/permissions.py` implement identical logic | Consolidate to one class |
| **`SystemAuditLog` action types unused** | `USER_SUSPENSION` and `HAZARD_OVERRIDE` are declared but never written | Implement them or remove them |
| **`HazardFlag.notes` is unused by the frontend** | The API accepts it; the UI only sends `reason` | Either surface it in the flag form or remove it |
| **`HazardFlag.status` never changes** | Defaults to `"pending"`; nothing ever resolves it | Set it to `resolved`/`dismissed` when a moderation action lands |
| **Login accepts email but the field is named `username`** | Works, but is a minor API smell | Rename to `identifier` in a future version |
| **Hardcoded `192.168.x.x` in the `.bat` scripts** | Points at one developer's machine | Use `localhost` |
| **Superuser bypass in role resolution** | `is_superuser` always resolves to `admin` regardless of `profile.role` | Intentional, but should be documented in the admin UI |
